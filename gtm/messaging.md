## One line

DocStar writes and hosts your API docs, and keeps them in sync, for the people and the AI agents that use your API.

## The short version (use as the base for every email)

> Most API docs are written once and then fall behind the code. Customers hit wrong examples, integrations stall,
> and support answers the same questions again and again. More and more of your users now build with AI coding agents,
> which need docs they can read and use directly.
>
> **DocStar** fixes that. Paste one setup prompt into Claude Code, Cursor or Codex and the agent reads your API's routes
> and writes the docs. You don't need an OpenAPI file, but you can import one (or Swagger or Postman) if you have it.
> From that one source, DocStar publishes:
>
> - a docs site with a try-it playground, code samples, search and AI answers, on your own domain
> - `llms.txt` and a markdown version of every page, so AI tools read your docs correctly
> - a hosted **MCP server** with OAuth sign-in, so agents can search, read and call your API
> - a **CLI** where every endpoint becomes a terminal command
> - an OpenAPI 3 export, so you are never locked in
>
> After launch, DocStar watches your GitHub repo and drafts doc fixes when routes, params or responses change. You review
> and publish. Analytics show what people and agents look for and where they get stuck.
>
> The free plan includes unlimited pages and a custom domain. Pro is $25/month for 10 members.
>
> → Try it free at **docstar.io**

## Why documentation matters (talking points)

- Docs are where developers decide whether to adopt an API. Bad docs lose deals quietly.
- Wrong docs create support tickets and failed integrations.
- AI agents now read docs on a user's behalf. If agents can't use your docs, they guess, and the integration breaks.
